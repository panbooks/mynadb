# v0.7.0 — Table Ownership and Partition-Aware Routing

This milestone reshapes cluster metadata around table ownership while adding physical partition discovery and cache-affinity routing. It also introduces the first cluster admin console and connects lease expiration more directly to recovery.

- **Source commit:** [`c49b32e`](https://github.com/panbooks/mynadb/commit/c49b32e1b35f75f473da1ed60fc8d4ed33ae1c5b)
- **Changes since:** `v0.6.0` — **78 commits**, including merged branch commits where present
- **Historical development period:** February 3, 2026 – February 6, 2026

## What's included

### Ownership and routing

- Replace the old file/partition ownership APIs and ISR model with table-level metadata and routing.
- Support multiple table owners, write rerouting, distributed writes across primaries, and scatter/gather queries for distributed tables.
- Move table rebalancing to the Meta leader and reduce duplicate ownership registrations with pending guards.
- Integrate lease expiration with recovery, drained-node cleanup, and retirement-time memtable flushing.
- Add ephemeral table ownership with TTL and table-cache eviction.

### Physical storage and query discovery

- Introduce Hive-style `date=.../node_id=...` physical partitions.
- Add object-store partition discovery, partition-level query routing, and SQL rewriting for cache affinity.
- Migrate retention, compaction, and the custom Parquet provider to the object-store abstraction, including prefix deletion.
- Remove temporary legacy-prefix handling after the routing transition.
- Add WAL handling to cluster RecordBatch writes, split partition caches, and standby query failover.

### Operator and developer tools

- Introduce the initial cluster admin console and improve its API client/dashboard.
- Reorganize source, scripts, and documentation; split large modules and improve development build configuration.

## Compatibility and upgrade notes

- **Table-level ownership is the authoritative Meta model.** Physical partition routing is a read-routing layer; it does not restore the earlier partition-replica registry.
- The Hive partition layout differs from the node-first paths used in earlier cluster stages. Review existing object paths and plan migration explicitly; automatic migration is not certified here.
- Legacy fencing/replica event fields and APIs are removed or reworked; cluster components should use matching tagged source/configuration.
- The initial admin frontend has separate build/workspace requirements. The React replacement arrives in v0.8.0.

## Important limitations

- The continuous-aggregate refresh executor inherited from v0.6.0 remains a placeholder.
- The later standardized `DataLayout`, heterogeneous-schema fixes, and expanded admin integrations are not all present in this snapshot.
- Routing, standby, object-store, and upgrade behavior were inspected in source but not exercised in a multi-node runtime test for this review.

## Building this tagged source

```bash
git clone --branch v0.7.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin mynadb
```

The default debug executable is `target/debug/mynadb`. This tag's Cargo
package is `mynadb 0.1.0`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

# v0.9.2 — Dependency and Documentation Maintenance

This maintenance release synchronizes admin-UI lockfile metadata and refreshes the repository README with setup, usage, configuration, and branding guidance. Its delta from v0.9.1 contains only three commits and changes two files; it adds no database-engine feature.

- **Source commit:** [`d603624`](https://github.com/panbooks/mynadb/commit/d603624eb3b635734945f4f773d25ad7e10fe86f)
- **Changes since:** `v0.9.1` — **3 commits**, including merged branch commits where present
- **Historical development period:** July 16, 2026 – November 9, 2026

## What's included

### Admin UI dependency maintenance

- Synchronize `admin-ui/package-lock.json` after installation of the declared Radix checkbox dependency.
- Normalize peer/optional dependency metadata in the lockfile.

### README and onboarding

- Replace outdated setup/usage material with source-build prerequisites, standalone startup, and HTTP examples.
- Document line protocol, schema/table mapping, SQL examples, storage, maintenance, and local cluster entry points.
- Explain the local configuration's WAL/authentication/TLS limitations and the root configuration's host-specific paths.
- Add a centered logo, project title/tagline, and quick navigation links.

## Compatibility and upgrade notes

- Rust source, Cargo.toml, Cargo.lock, and build.rs are unchanged relative to v0.9.1. The tag does not introduce an engine API, data-format, or WAL migration.
- Run `npm ci` when rebuilding the admin UI with the synchronized lockfile; the UI build was not verified in the readiness run described below.
- Cargo still declares `mynadb 0.1.0`. The tag identifies this maintenance snapshot.
- The README's local developer configuration disables WAL and authentication and binds to all interfaces. Use disposable data and review configuration before evaluation.
- The promotion-readiness files, `examples/quickstart.toml`, and reusable smoke checker added on main after `d603624` are **not included in this tag**.

## Important limitations

- This release does not resolve inherited Iceberg interoperability, continuous-aggregate execution, automatic downsampling query substitution, or Router MySQL gaps.
- It does not provide new binary assets or certify a frontend build, client compatibility matrix, multi-node failover, or power-loss durability.

## Building this tagged source

```bash
git clone --branch v0.9.2 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --profile fast-release --jobs 4
./target/fast-release/mynadb -c dev/configs/standalone/local.toml standalone
```

Use the tag's developer configuration with disposable local data. It uses ports
7000/7001/7002, disables WAL/authentication/TLS, and binds to all interfaces.
Stop with Ctrl+C or the matching `-c dev/configs/standalone/local.toml stop`
command. Review writable paths and listener settings before starting.

## Verification scope

Prior readiness validation used this **exact source commit, `d603624`**, on Oracle Linux 9.5 / WSL2 x86_64 with Rust/Cargo 1.92.0 and protoc 29.3:

- `cargo build --locked --profile fast-release --jobs 4` passed. The resumed build used cached artifacts from an interrupted attempt, so its duration is not a clean-container build-time benchmark.
- The unchanged README developer configuration passed startup, health, HTTP write, explicit flush, SQL result checking, CLI stop, restart, and persisted query checks.
- Selected library tests passed: **22 line-protocol, 2 WAL entry/checksum, and 66 InfluxQL tests**—90 total, zero failures. The local package used opt-level=0 for test compilation; exact commands are in the evidence.

These checks do not constitute the full test suite, WAL crash/power-loss recovery, frontend validation, or independent new-user testing. They were performed in the earlier readiness review, not repeated for release-note generation.

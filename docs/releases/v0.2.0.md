# v0.2.0 — Initial High Availability

This milestone introduces the first master/replica HA implementation for the standalone Stats service, including replication, heartbeat monitoring, and promotion/failover machinery. It is an experimental architecture that is later removed in v0.3.0.

- **Source commit:** [`3f7d7af`](https://github.com/panbooks/mynadb/commit/3f7d7af6ab6f8fb307f076220e1101bafc4b6b87)
- **Changes since:** `v0.1.0` — **15 commits**, including merged branch commits where present
- **Historical development period:** January 13, 2026 – January 15, 2026

## What's included

### Replication and failover

- Introduce the HA manager and configurable master/slave roles, retaining the terminology used by this historical source.
- Add replication transport and replicated WAL-entry handling.
- Add heartbeat monitoring, node state management, and promotion/failover components.
- Provide default configuration examples, HA unit tests, and local master/replica test scripts.

### Documentation and operations

- Add shared-storage and cluster design proposals; these are proposals, not the later Raft-backed cluster implementation.
- Expand Flight, HA, line-protocol, and retention documentation and repair navigation links.
- Correct logging retention settings.
- Align the metric-sender query schedule with configured intervals.

## Compatibility and upgrade notes

- The executable remains **`tsdb-stats`**, with Cargo package `stats 0.2.8`.
- Configure the tag's `[ha]` role, replication, heartbeat, and failover settings explicitly before trying a multi-process deployment.
- This master/replica implementation is **not** the Router/Data/Meta architecture introduced in v0.5.0, or the no-promotion standby design introduced in v0.6.0.
- v0.3.0 removes this HA subsystem. Do not assume that an HA configuration from this tag remains supported by subsequent versions.

## Important limitations

- Added tests and failover code are not evidence of verified zero downtime, partition safety, or a supported production topology.
- Metric field values are still not persisted as general queryable columns in this snapshot, as in v0.1.0.
- The inherited asynchronous-WAL defaults and early Basic authentication require deliberate configuration. TLS and multi-tenant RBAC are not part of this tag.

## Building this tagged source

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin tsdb-stats
```

The default debug executable is `target/debug/tsdb-stats`. This tag's Cargo
package is `stats 0.2.8`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

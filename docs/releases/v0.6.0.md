# v0.6.0 — Recovery, Standby Redesign, and Controlled Scale-In

This milestone focuses on cluster lifecycle behavior: graceful retirement, write/query handling during node removal, standby cache synchronization, and a no-promotion recovery design. It also introduces a continuous-aggregate framework whose refresh execution remains incomplete.

- **Source commit:** [`bb96dda`](https://github.com/panbooks/mynadb/commit/bb96dda3e15d86607a047356985aecf6e9e1498e)
- **Changes since:** `v0.5.0` — **51 commits**, including merged branch commits where present
- **Historical development period:** January 30, 2026 – February 2, 2026

## What's included

### Graceful retirement and recovery

- Reject new writes on retiring nodes, track in-flight queries, flush before exit, and enforce retirement timeouts.
- Add query retry and file-redistribution paths for connection/node failures.
- Introduce ratio-aware scale-in planning, health checks, recovery checks, and node-level primary/standby pairing.
- Replace promotion-oriented standby recovery with a **no-promotion** architecture.
- Trigger Data-node flushing from recovery events and add flush checkpoints for standby-cache synchronization.

### Cluster correctness and operations

- Fix heartbeat/lease expiration, node registration, cluster write distribution, and MinIO table discovery.
- Refresh query tables after cluster flush and Flight FLUSH actions.
- Add distributed compaction locks and rotate WAL before flush to protect the concurrent-write path.
- Standardize cluster port conventions, expand Router schema/table/memory/partition APIs, and add local/MinIO development modes.
- Add Raft tests and replace no-op assertions in existing tests.

### Continuous-aggregate framework

- Introduce aggregate definitions, watermarks, storage, refresh scheduling interfaces, and query-rewrite helpers.

## Compatibility and upgrade notes

- Use the new no-promotion standby configuration; old promotion assumptions and settings are superseded.
- Node retirement and recovery behavior now depends on pairing, health, checkpoint, and timeout settings.
- Use this tag's role-specific configuration and port conventions; earlier Meta/HTTP port assumptions may no longer apply.
- Cargo package metadata is now `mynadb 0.1.0`, independently of the retrospective `v0.6.0` milestone label.

## Important limitations

- **Continuous aggregates are a framework, not working automatic materialization.** The refresh job contains simulated logic and the default DataFusion refresh executor returns `(0, 0)`.
- Node-level lifecycle mechanisms still precede the table-ownership redesign in v0.7.0.
- Added scale-in and fault-tolerance tests were not rerun for this tag; no lossless-recovery or production-readiness claim is made.

## Building this tagged source

```bash
git clone --branch v0.6.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin mynadb
```

The default debug executable is `target/debug/mynadb`. This tag's Cargo
package is `mynadb 0.1.0`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

# v0.0.0 — Standalone Database Foundation

MynaDB's first historical milestone establishes a standalone Rust service for
HTTP ingestion, Arrow-based buffering, local Parquet storage, and SQL queries
through Apache DataFusion. It also introduces database management, date
partitioning, compaction, series-cardinality tracking, Arrow Flight queries,
and MySQL wire-protocol connectivity.

This is an early development snapshot. The source at this tag still uses the
**Stats** name; it predates the MynaDB rename and later durability, clustering,
and telemetry integrations.

- **Tag:** `v0.0.0`
- **Source commit:** [`aaaabda`](https://github.com/panbooks/mynadb/commit/aaaabda451a85a3fba106ca317e385c6e88fcc59)
- **Historical development period:** December 22–27, 2025
- **Scope:** the first 43 commits, corresponding to milestone M1

## What's included

### Ingestion and buffering

- HTTP write endpoints: `POST /write/:db` and `POST /write?db=:db`.
- Line-protocol input handling for measurements, tags, and optional nanosecond
  timestamps. See the field-value limitation below.
- In-memory Arrow record batches, periodic flushing, and explicit `POST /flush`.
- Configurable cache memory accounting, rejection when the cache is full, and
  a flush notification at 80% of the configured capacity.

### Storage and maintenance

- Local Parquet files organized by database/catalog, schema, measurement/table,
  and Hive-style `date=YYYY-MM-DD` partitions.
- Configurable schema extraction from service-related tags, with a fallback
  schema and prefixes for numeric schema names.
- Leveled minor and major compaction, background compaction, and manual
  compaction endpoints, including support for nonpartitioned tables.
- Schema merging and batch alignment in the Parquet writing and compaction paths.
- Partition listing, deletion, and explicit age/date-based cleanup endpoints.

### Queries and client interfaces

- DataFusion SQL execution over persisted Parquet data, with HTTP GET/POST
  query endpoints and JSON results.
- Catalog/schema/table registration and database/table management endpoints.
- Arrow Flight query results through `DoGet`.
- Initial MySQL wire-protocol connectivity backed by the query engine.

### Series tracking and configuration

- Hash-based series tracking for service, measurement, and tag combinations.
- Date-partitioned series metadata, background persistence, and the
  `GET /pmc/:db` statistics endpoint.
- TOML configuration selected with `-c` / `--config`, configurable listeners,
  file logging and rotation, and health/cache-statistics endpoints.

## Important limitations

- **Metric field values are not stored in this snapshot.** The tagged `Point`
  type contains measurement, tags, timestamp, and date; field-value parsing was
  removed during M1. For example, the numeric `usage` value in
  `cpu,host=server01 usage=23.5` is not persisted as a queryable `usage` column.
  This tag should not be described as a complete metric-value time-series database
  or as fully InfluxDB-compatible.
- **Flush before querying newly ingested data.** The query engine reads persisted
  Parquet files; querying unflushed in-memory data is a later milestone.
- **There is no WAL or crash-recovery guarantee.** Buffered, unflushed data can
  be lost when the process exits unexpectedly.
- Arrow Flight `DoPut` is unimplemented. MySQL connectivity does not imply full
  MySQL feature compatibility.
- This tag does not include authentication, TLS, distributed clusters,
  object-store backends, Prometheus ingestion, or OTLP ingestion.

## Using this historical tag

```bash
git clone --branch v0.0.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked
cp config.toml config.local.toml
# Edit storage.data_dir and logging.log_dir to writable local paths.
# Bind the server listeners to loopback for local evaluation.
./target/debug/stats -c config.local.toml
```

The package version in this snapshot is `stats 0.1.0`, despite the historical
milestone tag being `v0.0.0`. Its executable is `stats`, its CLI identifies as
`stats-service`, and the time column is named `timestamp`. The default ports are
HTTP **7000**, Arrow Flight **7001**, and MySQL **7003**. Do not substitute the
current `mynadb` executable, node subcommands, or current default MySQL port.

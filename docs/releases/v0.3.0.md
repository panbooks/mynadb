# v0.3.0 — Object-Store Architecture and Execution Improvements

This milestone resets the storage architecture toward a general time-series engine. It adds an object-store abstraction, persists typed metric fields, and restructures write and query execution while removing the earlier specialized cardinality and HA subsystems.

- **Source commit:** [`4f71930`](https://github.com/panbooks/mynadb/commit/4f71930eeaa054b8381a6ec68650f6394eebf609)
- **Changes since:** `v0.2.0` — **22 commits**, including merged branch commits where present
- **Historical development period:** January 19, 2026 – January 22, 2026

## What's included

### Storage and the data model

- Add a storage abstraction for local files and S3-compatible backends, with configuration paths for S3, MinIO, and OSS.
- Persist typed line-protocol field values in Arrow record batches: floating-point, signed integer, string, and boolean fields.
- Rework WAL storage and add periodic persistence scheduling and background WAL writing when synchronous writes are disabled.
- Sort batches by time before flush and use a sorted-stream merge during compaction.

### Write and query execution

- Shard write caches, cache conversion schemas, and parallelize larger line-protocol batches with Rayon.
- Add SQL `EXPLAIN` support and time-range pruning using Parquet statistics.
- Introduce table/Parquet metadata caches and query-result caching.
- Add partition pruning, parallel Parquet reading, and column projection pushdown.
- Return **HTTP 204 No Content** from successful writes.

## Compatibility and upgrade notes

- **Remove the original HA implementation**, specialized series tracker/deduplicator, and Go metric sender. Old HA and cardinality configurations are not a supported continuation of those subsystems.
- Successful writes now return **204**, replacing the earlier 200 response and text body; clients must not require the old response body.
- Although an intermediate commit mentions RiverDB, the tagged Cargo package is still `stats 0.2.8` and the executable is **`tsdb-stats`**.
- Review storage-backend credentials, endpoints, paths, and WAL settings. Storage and subsystem changes require an explicit data/configuration migration plan; no automatic cross-version migration is certified here.

## Important limitations

- Queries still rely on persisted files; the integrated memtable query path arrives in v0.4.0.
- The storage abstraction does not certify compatibility with every S3-compatible service.
- Historical throughput and QPS claims in commit messages are not new benchmark results for this release.
- This tag does not retain the v0.2.0 HA system and does not yet contain the later distributed cluster.

## Building this tagged source

```bash
git clone --branch v0.3.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin tsdb-stats
```

The default debug executable is `target/debug/tsdb-stats`. This tag's Cargo
package is `stats 0.2.8`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

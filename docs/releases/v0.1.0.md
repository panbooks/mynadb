# v0.1.0 — Durability and Standalone Operations

This milestone extends the standalone Stats service with write-ahead logging, startup recovery, background retention, authentication, and operational tooling. It builds on the local Arrow/Parquet and DataFusion foundation from v0.0.0.

- **Source commit:** [`3291005`](https://github.com/panbooks/mynadb/commit/3291005a749c09599172f59c549ee99233575fb7)
- **Changes since:** `v0.0.0` — **65 commits**, including merged branch commits where present
- **Historical development period:** December 29, 2025 – January 12, 2026

## What's included

### WAL and recovery

- Add a write-ahead log for incoming data writes and series tracking, with startup replay.
- Flush replayed data after recovery; correct WAL rotation and cleanup behavior.
- Add recovery mode handling that retains WAL files while recovered data is being flushed.
- Expose WAL synchronization, rotation, and retention settings.

### Retention, series tracking, and compaction

- Add background retention and date-aware series-cache retention, including startup cache loading and per-database caches.
- Introduce Bloom-filter-based series deduplication and configurable per-schema Bloom settings.
- Extend physical/user metric cardinality tracking (PMC/UMC), configurable schema/table mapping, and track-only mode.
- Add age-based and full compaction, concurrent table compaction, I/O rate limiting, and separate full-compaction concurrency limits.
- Skip oversized compaction candidates and improve top-level compaction handling.

### Operations and developer experience

- Add configurable Basic authentication and authentication test scripts, including URI credential handling.
- Add memory diagnostics, CPU/heap profiling, and build/version information.
- Improve parallel cache loading and register only the table needed by a query.
- Add Go metric-sender tooling, deployment scripts, a systemd service example, and the first documentation website.

## Compatibility and upgrade notes

- The MySQL default port changes from **7003 to 7002**.
- The executable is now **`tsdb-stats`**, while the package remains `stats`; Cargo declares version `0.2.8`, independently of this retrospective tag.
- Review the schema/table mapping and `[series_tracker].track_only` setting: track-only mode skips raw data ingestion.
- An experimental compaction memory budget was added and removed within this interval; it is not a shipped control in this tag.

## Important limitations

- Metric field values are still absent from the tagged `Point` type. Raw records contain measurements, tags, timestamps, dates, and extracted service/schema information; this is not yet general metric-value storage.
- `sync_on_write` defaults to **false**. WAL implementation and normal replay do not establish power-loss durability; select and test the intended synchronization policy.
- Authentication uses the early single-account Basic-auth configuration. Multi-tenant RBAC and TLS are later milestones.
- HA replication and distributed clustering are not included yet.

## Building this tagged source

```bash
git clone --branch v0.1.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin tsdb-stats
```

The default debug executable is `target/debug/tsdb-stats`. This tag's Cargo
package is `stats 0.2.8`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

# v0.8.0 — Operator Console, Ecosystem Integrations, and Time-Series Analytics

This milestone expands MynaDB's operator and SQL surface with a React admin dashboard, observability integrations, RBAC/TLS configuration, streaming queries, and analytical functions. It also standardizes storage layout and improves cluster catalog discovery.

- **Source commit:** [`ad8a4be`](https://github.com/panbooks/mynadb/commit/ad8a4be5579c314ccce1490d52a2d3fb12bd0282)
- **Changes since:** `v0.7.0` — **50 commits**, including merged branch commits where present
- **Historical development period:** February 6, 2026 – February 7, 2026

## What's included

### Operator experience

- Replace the early admin frontend with React and consolidate its backend APIs.
- Add a SQL Query Console, Storage Browser, metrics views, streamed events, filtering, export, notifications, and election/config/debug tools.
- Add test-data generation, schema/table selectors, object-store discovery fixes, and cluster Data-node compaction startup.
- Standardize data directories with `DataLayout` and improve storage/shutdown messages.

### Protocols, security, and observability

- Add Prometheus remote read/write handlers and a dedicated InfluxQL parser/transpiler.
- Add Grafana datasource plugin source and query tracing/profiling.
- Introduce multi-tenant RBAC, custom roles, user-management APIs, query isolation, audit logging, and TLS support in server implementations.
- Add WebSocket/SSE query subscriptions.

### Analytics and storage

- Add policy-based downsampling jobs and tier tables, integrated into standalone startup.
- Add adaptive per-column compression and age-based recompression.
- Add geospatial UDFs and forecasting aggregates using linear, EMA, and ARIMA models.
- Expand columnar cache dictionary encoding and predicate evaluation.
- Fix several cluster query, catalog, response, and path-handling problems found during integration work.

## Compatibility and upgrade notes

- Build the React admin package separately; the removed early frontend/workspace layout is not interchangeable with it.
- `DataLayout` introduces explicit `store`, `wal`, `meta`, `cache`, `system`, and `run` locations. Check storage paths and existing data before upgrading.
- Authentication changes from the earlier single-account model to role/user configuration. Review credentials, permissions, TLS paths, and deployment-role coverage.
- Cargo still declares `mynadb 0.1.0`; the release tag identifies this historical milestone.

## Important limitations

- Router MySQL is still explicitly unimplemented, and protocol/TLS availability must be checked per deployment role.
- **Automatic downsampling query substitution is incomplete:** the analyzer logs a proposed tier but returns the unchanged plan. Query materialized tier tables explicitly.
- The separate continuous-aggregate refresh executor remains a placeholder.
- Grafana plugin signing, catalog publication, and real-client compatibility are not established by the presence of plugin source. Geospatial functions do not imply full PostGIS compatibility, and forecasting code does not establish forecast accuracy.
- OTLP and Iceberg are introduced in v0.9.0, not this tag.

## Building this tagged source

```bash
git clone --branch v0.8.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin mynadb
```

The default debug executable is `target/debug/mynadb`. This tag's Cargo
package is `mynadb 0.1.0`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

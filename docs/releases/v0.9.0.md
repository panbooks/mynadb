# v0.9.0 — Correctness Hardening and Observability Ingestion

This milestone addresses query, schema, storage, and Grafana integration problems while introducing native OTLP ingestion, a built-in monitoring dashboard, and an initial Iceberg metadata/catalog implementation.

- **Source commit:** [`4a147b4`](https://github.com/panbooks/mynadb/commit/4a147b44089659f697c1287ea9fbdcc3aeed79f9)
- **Changes since:** `v0.8.0` — **41 commits**, including merged branch commits where present
- **Historical development period:** February 9, 2026 – February 14, 2026

## What's included

### Query and storage correctness

- Align heterogeneous memtable/Parquet schemas by name, merge file schemas, normalize dictionary columns, and correct union projections and empty/count projections.
- Add compaction manifests to avoid reading overlapping files twice; merge duplicate points and coalesce rows with heterogeneous field sets.
- Fix missing-table/field handling, distributed reaggregation of non-numeric columns, suspect-node deadlocks, and partial query results.
- Fix compaction path discovery and standalone shutdown behavior.
- Preserve full schemas in hot-partition cache entries, invalidate after compaction, detect staleness, and disable that cache by default.

### Ingestion and Grafana compatibility

- Add InfluxDB-compatible query/metadata endpoints and fixes for Grafana/Telegraf query translation, response shapes, time-bucket arguments, grouping, and epoch precision.
- Add quote-aware and escaped-space-aware line-protocol parsing.
- Support gzip write bodies and increase the request-body limit to **250 MB**.
- Add last-point query handling and avoid repeated InfluxQL parsing.
- Add query-cost logging and a built-in system monitoring dashboard.

### OTLP, Iceberg, and validation assets

- Add OTLP HTTP/gRPC services and converters for metrics, logs, and traces.
- Add initial Iceberg table metadata, snapshots, REST catalog endpoints, and synchronization code.
- Add 122 HTTP integration tests across seven suites and expand recorded benchmark documentation.

## Compatibility and upgrade notes

- Hot-partition caching now defaults to disabled; deployments that enabled it should review the corrected behavior and staleness settings.
- Configure OTLP and Iceberg explicitly. Their top-level enabled settings default to false in this snapshot.
- The larger request-body limit and gzip decoding change ingestion resource requirements; size client batches for the available memory.
- The separate distributed `GROUP BY time(...)` alias-resolution fix and dashboard response-unwrapping change arrive in v0.9.1.

## Important limitations

- **Iceberg manifests and manifest lists are serialized as JSON in this implementation**, rather than the Avro manifest representation required for full interoperability. Spark/Trino/Flink compatibility is not certified.
- OTLP converters and service code do not establish compatibility with every SDK, Collector version, metric kind, or deployment role.
- Router MySQL, automatic downsampling query substitution, and continuous-aggregate execution retain their earlier limitations.
- The 122 added tests and recorded benchmark files are source/history evidence; they were not rerun for this tag in the release-note review, and no performance-leadership claim is made.

## Building this tagged source

```bash
git clone --branch v0.9.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin mynadb
```

The default debug executable is `target/debug/mynadb`. This tag's Cargo
package is `mynadb 0.1.0`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.

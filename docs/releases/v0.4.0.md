# v0.4.0 — Query-Engine Maturity and Validation

This milestone gives the project its MynaDB name and recognizable standalone query architecture: queries can combine fresh in-memory data with persisted Parquet, while custom providers, metadata management, and time-series functions expand the SQL path.

- **Source commit:** [`64acecb`](https://github.com/panbooks/mynadb/commit/64acecbd0c5f63258d742a6797a3c32ac5d4a45a)
- **Changes since:** `v0.3.0` — **49 commits**, including merged branch commits where present
- **Historical development period:** January 23, 2026 – January 24, 2026

## What's included

### Fresh-data and time-series queries

- Integrate memtable data into query execution so fresh writes can be queried before Parquet flush.
- Add custom Parquet table providers and union providers for memory/file-backed data.
- Add `GROUP BY time(...)` transformation, time bucketing/fill helpers, and `first()` / `last()` aggregation functions.
- Include buffered tables in MySQL database/table discovery.

### Metadata, caching, and layout

- Introduce in-memory metadata management and local disk caching for remote Parquet files.
- Add read-side Bloom-filter use, predicate pushdown, hot-partition caching, and metadata/cache invalidation integration.
- Add cardinality-based tag ordering to flush and compaction paths.
- Reorganize query code into analyzers, optimizers, providers, functions, and cache modules.

### Validation and documentation

- Add correctness, chaos, fuzz, integrity, concurrency, edge-case, benchmark, and public-dataset validation suites.
- Replace fuzz stubs with calls to library code and add expected-result checks to dataset tests.
- Update documentation, project branding, and the myna-bird logo.

## Compatibility and upgrade notes

- **Rename the executable and package to `mynadb`.** The package version at this tag is still `0.2.8`; the milestone tag is a separate version label.
- **Rename the time column from `timestamp` to `time`.** Update SQL, client mappings, and dashboards; existing files and dependent queries need migration testing.
- The standalone cache flush interval changes to 60 seconds in this interval.
- Time-grouping transformations are not the dedicated InfluxQL parser/transpiler introduced later in v0.8.0.

## Important limitations

- Memtable visibility does not make unflushed writes durable; WAL and synchronization settings still determine recovery behavior.
- Hot-partition caching receives correctness fixes and is disabled by default in v0.9.0; its presence here should not be treated as evidence that those later fixes are already included.
- Added test suites were not rerun for this historical tag during the release-note review. No performance superiority or full InfluxDB compatibility is certified.
- This is a standalone milestone; the Router/Data/Meta cluster is introduced in v0.5.0.

## Building this tagged source

```bash
git clone --branch v0.4.0 --depth 1 https://github.com/panbooks/mynadb.git
cd mynadb
cargo build --locked --bin mynadb
```

The default debug executable is `target/debug/mynadb`. This tag's Cargo
package is `mynadb 0.2.8`; its package version is separate
from the retrospective release tag. Before starting a service, use configuration
from this tag and review writable data/log paths, listeners, storage credentials,
and durability settings. Build prerequisites vary across these historical snapshots.
